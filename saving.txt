SECRET SAVING / RESTORE RUNBOOK
================================

Why this file exists
--------------------
This repo currently uses secrets in several different places:
- root OAuth files
- nested service .env files
- service credentials directories
- Lightning / PostgreSQL / Google Drive runtime settings

If you change machine or clone to a new environment without these files, the app will not run correctly.

Canonical layout from now on
----------------------------
- secrets/shared.env
- secrets/env/
- secrets/db/
- secrets/api/
- secrets/oauth/oauth2_credentials.json
- secrets/oauth/oauth2_token.pickle
- secrets/google-drive/drive-sa.json
- secrets/deploy/
- secrets/docker/
- secrets/gpu/

Recommended policy
------------------
- Do not commit raw secrets in plaintext.
- If you need portability across machines, commit only an encrypted bundle.
- Keep the bundle passphrase outside git: password manager, 1Password, Bitwarden, etc.

Safe backup flow
----------------
0. One-time migration into the canonical layout:

   python scripts/init_project.py

1. Export encrypted bundle:

   SECRET_BUNDLE_PASSPHRASE='your-strong-passphrase' \
   bash scripts/export_secrets_bundle.sh

2. This creates:
   - secret_backups/secrets_bundle_<timestamp>.tar.gz.enc
   - secret_backups/secrets_bundle_<timestamp>.manifest.txt

3. You may commit the .enc file if needed.
   Do not commit the raw `secrets/` contents.

Restore flow on a new machine
-----------------------------
1. Clone repo.
2. Pull or copy the encrypted bundle.
3. Restore secrets:

   SECRET_BUNDLE_PASSPHRASE='your-strong-passphrase' \
   bash scripts/import_secrets_bundle.sh secret_backups/secrets_bundle_<timestamp>.tar.gz.enc

4. Then install dependencies and run services as normal.
   For Docker Compose, use:

   cd Multi-Camera-Person-Tracking-and-Re-Identification
   docker compose --env-file ../secrets/shared.env up --build

Validation flow
---------------
Run the readiness audit any time:

   python scripts/check_secret_readiness.py

To save the report into docs:

   python scripts/check_secret_readiness.py \
     --write-report docs/SECRET_AUDIT_REPORT_$(date -u +%Y-%m-%d).md

Git control improvements already applied
----------------------------------------
- recursive .env ignore

- credentials directory ignore

Manual cleanup you should keep
------------------------------
If a secret file was ever committed before, add it to .gitignore and remove it from the index:

   git rm --cached oauth2_credentials.json oauth2_token.pickle

Then commit the cleanup.

What to rotate first if you suspect leakage
-------------------------------------------
- LIGHTNING_API_TOKEN
- POSTGRES_PASSWORD
- JWT_SECRET_KEY
- Google Drive service-account credentials
- OAuth refresh token / oauth2_token.pickle

Last note
---------
If you want fully reproducible onboarding, the best long-term setup is:
- keep examples in repo
- keep real secrets in encrypted bundle
- keep passphrase in password manager
- never rely on memory or scattered local .env files again
